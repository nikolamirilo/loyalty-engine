Events

An event is something a member does that another system reports, such as placing an order. Define each event once, then add rules that decide what it earns.

{{i:map-pin}} Where{{i:zap}} Events
{{h:steps|Define an event}}
  1. Select New event

    At the top right of the Events page.

  2. Enter a Name

    For example "Order placed". The API key under it, such as orderPlaced, is what your systems send. It never changes.

  3. Select Add attribute for each piece of data your system sends

    Each one adds an empty row.

  4. Give each row a label and a type

    Text, Number, Yes / No, Date or Dropdown. A dropdown needs its options, separated by commas.

  5. Select Create event"Event created. Add a rule, then turn it on." The event's page opens.
{{h:opts|Event settings}}
{{o:Name|req;lim=1 to 100 characters}}Must contain letters, and its first letter or digit must be a letter. Unique in the program.{{/o}} {{o:Description|opt}}Who sends it, and when.{{/o}} {{o:Attributes|opt}}Data sent with each event. Rules can check these values or copy them onto the member. All are optional when sending.{{/o}}
{{h:steps|Turn an event on or off}}
  1. Open the event

    Select its row on the Events page.

  2. Use the switch next to Active or Inactive

    At the top of the page. It saves at once."Event turned on." or "Event turned off. Incoming events are rejected."

[[warn New events start off]]

An event created in the console is Inactive. Your systems' events are rejected until you turn it on.

[[/]] {{h:rules|Good to know}}
  • The API key {{n:4}} is made from the letters and digits of the name in camelCase, up to 63 characters. It never changes, even if you rename the event.
  • While an event is off, its page says "This event is off, so incoming events are rejected and no rules run."
  • Events created by your developers through the API start on. Only the console creates them off.
  • An attribute's key and type never change. You can rename its label.
  • You cannot remove an attribute that a rule uses. Change or delete the rule first.
  • Events are listed oldest first.
{{h:risk|Delete an event}}

Deleting an event deletes its rules too. Events already received stay in each member's history and in the log, shown by their API key. It cannot be undone.

Rules

A rule says what an event does for the member: when the event happens, if all conditions hold, then all effects run. Add as many rules to an event as you need.

{{i:map-pin}} Where{{i:zap}} Events›an event›Rules
{{h:steps|Create a rule}}
  1. Select New rule

    On the event's page, in the Rules card.

  2. Enter a Rule name
  3. Add conditions under IF

    Optional. Pick a field, a comparison and a value. All of them must be true. With none, the rule runs on every event.

  4. Add effects under THEN

    A new rule starts with Earn points, 10 points. All effects run, in the order listed.

  5. Choose the LIMIT

    Every time the event happens or Only the first time per member.

  6. Read the sentence In plain words

    It describes the rule as you build it.

  7. Select Create rule"Rule created." New rules are on.

{{h:opts|Effects: what THEN can do}}
{{o:Earn points}}A fixed amount, or the value of a number attribute such as the event's amount. The member's tier multiplier applies. {{h:steps|Pause, edit or delete a rule}}
  1. Use the rule's switch {{n:4}}

    Pauses or turns on the rule at once. A paused rule shows Paused and is skipped.

  2. Select the pencil {{n:5}} to edit

    Select Save changes."Rule saved."

  3. Select the bin to delete

    New events stop triggering it. Events already received keep what they earned."Rule deleted."

{{h:ex|Example: a bonus for big app orders}}

When "Order placed" happens, if amount is at least 50 and channel is App, then give reward "Free espresso" and add member to segment "Big spenders", only the first time per member.

{{h:rules|How several rules work together}}
  • Every active rule whose conditions all match runs. There is no "first match wins".
  • Conditions look at the member as they were when the event arrived, so one rule never changes whether another rule matches.
  • Effects that depend on the current state still see earlier effects. A Burn after an Earn sees the new balance, and Add challenge progress works right after Assign challenge.
  • Rules run oldest first. There is no way to reorder them.
  • The tier is checked after every points change, and again after all rules ran. Earned points use the multiplier the member had when the event arrived.
{{h:rules|Good to know}}
  • A skipped effect never stops the others. The log says why it was skipped.
  • "Only the first time per member" counts a run even when every effect was skipped, for example because the reward was out of stock. Editing the rule keeps this history.
  • Rule names can be up to 100 characters.
  • "is not" also matches when the attribute was not sent, or the member has no tier.
  • For text, "is" needs an exact match, including upper and lower case. "contains" ignores case.
  • Points from a rule show in Points activity as "Effect of event Order placed".

Test an event

Send an event for a member from the console, the way your systems would, and see at once what the rules did.

{{i:map-pin}} Where{{i:zap}} Events›Test event
  1. Select Test event

    On the Events page, or on an event's page. The event must be on.

  2. Choose the Event

    Only active events are listed. On an event's page, the event is already chosen.

  3. Choose the Member
  4. Fill in attributes

    All optional. Empty ones are not sent.

  5. Select Send test eventA message such as "Event recorded. Earned 40 points. Added to segment "Big spenders"." or "Event recorded. No rules matched."

On a member's page, the Events card has Send event, which does the same for that member.

{{h:rules|Good to know}}
  • Test events are real. The member keeps everything the rules gave, and the event shows in the log.
  • Each test is a new event, so it is never treated as a duplicate.
  • The member list shows up to 1,000 members, with no search.
  • "(2 skipped)" at the end means two effects did not apply. The log shows why. If every effect was skipped, the message is "Event recorded. Nothing applied (2 skipped)."
  • "No rules matched" also appears when the matching rules already reached their per-member limit.
  • Test events go to the program selected in the console.

Event logs

See every event the program received, for which member, and what its rules did.

{{i:map-pin}} Where{{i:zap}} Events›{{i:clock}} Logs
{{h:steps|Read the log}}
  1. Open Events and select Logs
  2. Pick an event in the filter {{n:1}}

    Optional. All events shows everything.

  3. Read What happened {{n:2}}

    A green tick is an effect that applied. "Skipped:" gives the reason one did not. "No rules matched" means nothing ran. Hover a line to see the rule's name.

  4. Open the member

    Select their name.

{{h:rules|Good to know}}
  • The log shows the newest 200 events, with no paging.
  • The only filter is the event. There is no member, date or search filter. For one member's events, open their page.
  • Events that were rejected, such as for an inactive event, are not in the log.
  • Times are shown in your own time zone.

Send events from your systems

Give your developers what they need to report events, such as orders, from your till, shop or app to Loyalty Simulator.

{{i:map-pin}} Where{{i:zap}} Events›an event›Send this event
{{h:steps|Hand over the request}}
  1. Open the event
  2. Select the copy button on Send this event

    On the right side of the event's page. It copies a ready request.

  3. Send it to your developers

    With the values below.

{{h:opts|What a request contains}}
{{o:type|req}}The event's API key, such as orderPlaced. Not its name, and not the ID that Copy event ID copies.{{/o}} {{o:memberId|req}}The member's ID in this program. Copy ID on the member's page copies it.{{/o}} {{o:X-Program-Id|opt}}The program's ID or slug. If it is left out, the event goes to the default program.{{/o}} {{o:attributes|opt}}The attribute values, by key. Unknown keys are refused.{{/o}} {{o:eventId|opt;lim=1 to 200 characters}}Your own unique ID, such as the order number.{{/o}}
{{h:rules|Duplicates and errors}}
  • A repeat with the same eventId, type and member returns the first result and runs nothing, even if the event was turned off since. Use eventId so a retry never pays twice.
  • Without an eventId, every request counts as a new event.
  • Events for an unknown or inactive event type are refused and not recorded.
  • The response lists every effect of the rules that ran, applied or skipped, with the rule's name. A new event answers with status 201, a repeat with 200.
  • Every request needs the shared bearer token. Ask whoever runs the server for it.
  • Attribute values are checked against their type, and text is limited to 500 characters.
